## Why this stub exists and will not move again

The old path is cited from **archive** documents:

`decisions/DNA-2026-09-25_ontology-design-requirements.md:951` and `decisions/PROPOSED-2026-10-02_public-brand-examples.md` (three times) — and `mac.schema.json` cites §1 and §4 for the `never_axis` measurement

`guardrails/semantic_currency.yaml` names `decisions/` an archive alongside `protocol/`: *"Append-only.
Entries are never edited."* A record citing this path was TRUE on its date, and editing it would make
the record claim a layout that did not exist when it was written. `check_dangling_references` judges an
owned-root path like `reference_manual/column_rulings.md`, and `tools/dangling_floor.txt` is a one-way ratchet
that refuses a new waiver, so the reference cannot be set aside either.

Its sibling stubs, [`canon_library.md`](canon_library.md) and
[`canon/population_select.md`](canon/population_select.md), exist for the same reason.
