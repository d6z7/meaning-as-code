# RECORDED 2026-10-02 — the `label_of` worked example uses fictional marques

Asked for as a proposal; **acted on instead**, on the coordinator's ruling, because the repository
had already made the choice and was carrying the real marques beside it redundantly.

`check_mac_public` reported **39 findings** under its `brand-name` / `org-name` rules across nine
files. Every one of them was the same worked example — the one that explains `label_of`:

> *Brand is Contoso, known as Contoso. But Manufacturer registered name is Contoso, Ltd. One is
> what the world calls it, the other what the register calls it.*

These were public-knowledge car marques, not an estate's data. The gate cannot tell the difference,
and that is not a defect in the gate: a reader of a public repository cannot tell either.

---

## 1. Why substitution cost the example nothing

**The repository had already chosen the fictional pair.** `mac_vocabulary.yaml`'s `name_register`
term for `legal` shipped **two** examples of a statutory name — a real one and `'Contoso, Ltd'`. The
fictional half was already there, doing the same work, on the same line.

**And the page that teaches the ruling was already measured on the fictional estate.**
`reference_manual/column_rulings.md` prints a measured 1:1 label table two lines above the sentence
in question — `A. Datum / A. Datum Corporation 132`, `Contoso / Contoso, Ltd 710`,
`Fabrikam / Fabrikam, Inc. 267`, `Adventure Works / Adventure Works 192`. The sentence then switched
to real marques a reader could not check against anything on the page. After the substitution it
names rows of the table directly above it, so **the worked example became more verifiable, not
less** — which is the opposite of the cost a substitution usually carries.

## 2. The map

| now reads | role in the example |
|---|---|
| `Contoso` | the common-register name — what the world calls it |
| `Contoso, Ltd` | the legal-register name — what the trade register calls it |
| `Fabrikam Group` | the OWNING company, the counter-example that would be 1:N and NOT a label |
| `Northwind`, `Tailspin` | sibling marques of the same group (used in `decisions/`, not needed here) |

**The four names that were replaced are deliberately not restated in this file.** Writing them here
would re-open the findings the substitution just closed, and the per-line escape hatch is not an
option for a record whose purpose is that the tree is clean. They are in this change's own diff,
which is where a substitution belongs. The same five placeholders are already used by
`decisions/DNA-2026-09-25_ontology-design-requirements.md` §`label_of`, so the two read alike.

## 4. Flagged: one example collapsed

`mac_vocabulary.yaml`'s `legal` term listed the real statutory name **and** `'Contoso, Ltd'`. After
substitution the two examples were the same string, so the duplicate was dropped:

    legal:  "The name in a trade or statutory register. 'Contoso, Ltd'."

That line now names only the fictional pair, and together with `common` above it ("`'Contoso'`,
`'Germany'`, `'Monday'`") it is the one place a reader learns what the example means. No count or
measurement is involved, so nothing is weakened — but it is the one line where the substitution
removed text rather than replacing it, which is why it is recorded here.

## 5. Flagged: `grammar_map.html` cannot be regenerated today

Its five brand findings — and two absolute home paths from the same page — are **stale output**.
All three of its sources are already fixed (`gen_grammar_map.py`, `column_effects.yaml`,
`mac_vocabulary.yaml`), and the generator refuses to run, for a reason that has nothing to do with
this work:

    gen_grammar_map: rulings plane: mac_vocabulary.yaml#concept.column.ruling declares ['sort']
    and this plane has no `tests`/`key_of` row for it — add the row

`sort` was added to the ruling vocabulary and to `mac.schema.json` earlier today; the rulings plane,
`column_effects.yaml` and `column_specification.md`'s *Every key* table did not follow. That is a
designed stop, and it is doing its job. Completing it is **not** a scrub:

* the rulings plane's middle lane is *measurement → person → ruling*, and `sort` has **no
  measurement constellation** — the generator's row demands one, so the honest fix is a plane that
  admits a ruling nobody measures, which is a design decision for this page's author;
* `column_effects.yaml` and `column_specification.md`'s key table are each other's parity check
  (`gen_column_bench.py --check`), so a `rulings.sort` key must land in both at once.

So the row was left to its owner rather than invented here. **One regeneration of
`gen_grammar_map.py` after that row lands takes the public gate to zero** — the page's own inputs
are already clean, which the fix to the generator's provenance helper proves:

    runtime.root  : mac-platform/packages/mac-runtime/src/mac_runtime
    measured_from : mac-platform/packages/mac-runtime/src/mac_runtime
